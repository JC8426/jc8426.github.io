Research Interests.

Autonomous systems that can coordinate, adapt, and be tested.

01
Research question · Distributed autonomy

EASY coordination

How can local decisions produce intelligent swarm behaviour?

I am interested in how UAVs coordinate with limited communication and partial information. My research questions connect distributed decision-making, formation behaviour, and the constraints of local trajectory planning.

02
Method · Baselines and simulation

Hypothesis-driven ROS simulation

From a research question to a repeatable experiment.

I use the open-source EGO-Planner implementation as a baseline for my UAV research. ROS, Gazebo, and RViz help me set up scenarios, inspect trajectories, and compare behaviour as I change the assumptions.

03
Evaluation · Constraints and failure analysis

Real-world constraints and iterative validation

What survives the move from simulation to hardware?

Sensing uncertainty, latency, compute limits, and hardware variation shape the questions I want to test. I use logs and repeatable checks to trace failures and decide what the next experiment should examine.

How I work with agents.

I define the task. Agents help me build and investigate. The results guide the next decision.

HUMAN DIRECTION

Intent → scope → acceptance

I set the requirements, choose the trade-offs, and review the outcome.

01Frame the work−

A task an agent can act on.

I provide the relevant files, constraints, expected behaviour, and a clear stopping point. Independent tasks can run in parallel; shared decisions stay connected.

Requirements → task brief
02Build & investigate−

Code, experiments, and a record of changes.

I use coding agents to implement changes, inspect failures, and draft technical notes. Git keeps the changes inspectable so I can review what was actually produced.

Task brief → working change
03Test & decide−

The next step comes from the result.

I check the behaviour against the original task, read the test output, and look at the interface or experiment. Findings return to the task brief; an accepted result gets documented for reuse.

Evidence → revision or delivery
Feedback updates the next task
