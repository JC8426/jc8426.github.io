# 网页文案审阅 — 2026-09-09

这次审阅覆盖主页、项目索引、八篇案例的中英文文案。主要问题并不只是 not / but，而是标题英语不自然、抽象能力词过多、反复解释没有做什么，以及把未来计划写成与已完成项目同等分量的卡片。

## 本次改写

| 原表达或问题 | 当前处理 | 原因 |
|---|---|---|
| Involving Route. | Along the way. / 一路走来。 | 使用自然的经历标题，并用时间与具体工作说明成长。 |
| Workflow, in my style. | How I work with agents. | 明确说明读者能看到什么。 |
| Taste my taste. | What catches my eye. | 更接近日常摄影分享的语气。 |
| Layer 1 / 2 / 3 与泛化能力标签 | EASY coordination、Hypothesis-driven ROS simulation、Real-world constraints and iterative validation | 用研究问题、方法与评估对象组织内容。 |
| 技术笔记中的 Planned 占位 | 八个有实际案例落点的链接 | 让内容的可读性和证据强度一致。 |
| 反复用否定句界定原型 | 直接说明 local prototype、实现、测试及当前阶段 | 保留真实范围，同时减少防御式表达。 |
| 宣告式能力总结 | I provide the relevant files… / I check the behaviour… | 通过具体动作说明个人贡献。 |

## 保留的内容

Hero 的 Create. Beyond limitations. 是既有品牌标题，本次保留。它可以承担情绪表达，下面的项目与案例负责提供事实。科学分析中必要的适用范围仍保留，例如日志计数无法单独证明无线接收率，验证性能需要受控实验。不能为了删除否定词而让研究结论失真。

EASY 没有补写未经确认的全称或论文身份；EGO-Planner 被写为开源基线。XOPS 采用匿名原型表述，个人角色是需求主导与 AI 辅助实现。协作、概念设计、原型和实际验证继续区分，团队关系与私人交流未加入公开页面。

## 后续写作标准

先写做了什么、用了什么材料、观察到什么结果。用具体文件、界面、实验或数据解释能力。仅在理解范围确实需要时说明限制；避免每段都使用对照句和口号。没有测量依据时，不填效率提升百分比、部署规模或收益数字。
